# ADR-0024: v0.5 Uses Normalized Non-Streaming Provider Dispatch

| Field | Value |
|---|---|
| Status | Proposed |
| Date | 2026-08-01 |
| Deciders | Product Owner, advised by Chief Architect / CTO |
| Related | ADR-0010, ADR-0023, Chat Interface PRD |

## Context

The parked candidate called post-completion word chunking “streaming.” It did not exercise
provider-response deltas, mid-stream failure, cancellation, usage finalization, or partial
answer semantics. True streaming would enlarge the first real-provider release and its
security and accessibility matrix.

## Proposed decision

v0.5 supports one complete-response provider request per attempt through a versioned
provider gateway. It includes:

- the deterministic mock adapter for fixtures and contract tests; and
- exactly one Product Owner-approved real provider adapter for release evidence.

The application selects a model role and required capabilities, not a hard-coded model
name. The real adapter has an allowlisted destination, explicit credential source, timeout,
request/output limits, cancellation, normalized errors, usage and cost fields, and no
provider memory, tools, telemetry, fallback routing, or retry unless the application
authorizes it. Network is denied outside an approved dispatch.

Provider-response streaming and simulated word-by-word output are both excluded. The
normalized terminal states are `completed`, `failed`, `cancelled`, and `blocked`. A failed
or cancelled attempt cannot be marked completed, cited as an answer, or silently retried.
Unknown usage or cost is represented as unknown, never zero.

## Consequences

- v0.5 proves the provider and egress trust boundary without simultaneously solving
  partial-response retention and accessible streaming announcements.
- First-token latency is not a v0.5 gate. Complete-response latency is measured separately
  from provider delay and reported with provider/model configuration.
- A later streaming ADR must define event ordering, partial-content status, cancellation,
  citation timing, usage finalization, accessibility announcements, and reconnection.
- Two adapter implementations pass one normalized contract suite, but only the real adapter
  establishes network evidence.

## Alternatives rejected for v0.5

- Post-completion chunking: rejected because it misrepresents terminal output as provider
  streaming.
- Provider-native streaming now: deferred because it is not necessary for the smallest
  trustworthy conversation slice.
- Mock-only release: rejected because it would not deliver or test a real conversational
  provider boundary.

## Revisit conditions

Revisit after the non-streaming provider, egress, cancellation, evidence, and privacy
contracts pass release evidence with the approved real adapter.
