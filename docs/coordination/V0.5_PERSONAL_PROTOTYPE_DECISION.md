## Direction

JARVIS is currently a personal system for its Product Owner. Formal distribution, unattended
Windows deployment, clean-room A12 certification, and release-grade reproducibility are not
prerequisites for determining whether the system is useful.

The v0.5 full-certification route is paused. Its VM, media, tooling, evidence, and findings are
preserved for possible future resumption, but no remaining certification task is on the
prototype critical path.

The active objective is now a local developer prototype that lets Jason use the existing
JARVIS frontend with Jarvis Core through a safe, mock-first integration, followed by one
explicitly approved Google Gemini pilot when the local workflow is accepted.

## Prototype sequence

1. CTO reconciles the accepted Voice Shell bridge plan with the exact current Jarvis Core v0.5
   application API and issues one implementation-ready local-prototype brief.
2. Engineering implements a one-way `Voice Shell -> VoiceCoreBridge -> Jarvis Core` mock-first
   integration without the quarantined legacy runtime or live audio.
3. Quality verifies the local workflow and its approval, cancellation, citation, coverage,
   redaction, and failure states.
4. Product Owner performs a local usability pilot. A separate decision is required before the
   first real Google API call or any credential materialization.

## Preserved future gates

Before any public distribution or claim of release readiness, the paused certification chain
must be re-planned and completed, including packaging/recovery evidence appropriate to the
intended distribution. Nothing in this decision waives those future requirements.

## Exclusions

This decision does not authorize unattended Windows installation, VM repair or cleanup, A12,
publication, release, merge, push, live provider calls, credential entry, spending, real audio,
legacy runtime connection, tools, vault writes, or network access.
