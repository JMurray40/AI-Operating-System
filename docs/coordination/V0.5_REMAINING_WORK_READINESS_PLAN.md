## Consolidated prerequisite audit

Before Wave 1, one read-only audit must establish all of the following:

- official ADK and KB links remain available and exact;
- Microsoft redirect chain, mandatory proxy, license/EULA route, and storage capacity are known;
- native administrator elevation works for the intended operator and no restart is pending;
- network can be enabled narrowly for acquisition and proven denied for installation/testing;
- Authenticode and complete-file inventory tooling are available;
- accepted ISO, target VM, rollback VHDX, switches, NAT/bridge/ICS, and Default Switch remain exact;
- Hyper-V works under the elevated execution identity and can create a zero-NIC Gen2 test VM;
- basic console access works for synthetic and Product Owner actions;
- Jason's private account transitions have exact start and stop boundaries;
- private storage has sufficient capacity and is outside repositories and synchronized folders;
- cleanup objects and retention rules are listed before creation; and
- A12 inputs, runtime, network denial, Quality scope, and release outputs remain available.

Any red item leaves readiness `draft`. No acquisition begins merely because Handoff 91 names the
tools.

## Five execution waves

### Wave 1 — Official tooling acquisition and acceptance

Acquire the exact ADK offline layout and KB patch under narrow network controls, then independently
bind signatures, versions, layout members, hashes, licenses, and proxy/TLS evidence. No
installation occurs. Estimated active time: **1–3 hours**.

### Wave 2 — Offline tooling installation and acceptance

With network denied, install only Deployment Tools, apply KB5101684, and independently verify the
host delta, serviced executables, zero PATH change, restart state, rollback identity, and elevated
Hyper-V boundary. Estimated active time: **1–2 hours**.

### Wave 3 — Catalog, answer media, and two synthetic proofs

Generate the catalog, author the minimal answer file, build the answer ISO twice, and run two fresh
zero-NIC synthetic installations. Independently validate semantics, OOBE/account behavior,
reproducibility, privacy, and isolation. Estimated active time: **3–6 hours**.

### Wave 4 — Target preparation, Product Owner install, and baseline

Preserve the partial VHDX, attach a new VHDX and accepted media while powered off, perform
independent preflight, allow Jason one private installation/account transition, verify the
powered-off result, and create one separately controlled clean checkpoint. Estimated active time:
**2–4 hours**, plus Jason's interaction.

### Wave 5 — A12, limited Quality, and release decision

Run the prepared offline install/uninstall/recovery/reinstall matrix, obtain limited Quality
revalidation, decide WP4, and route formal release or developer-preview disposition. Estimated
active time: **2–4 hours**.

## Conditional authorization envelope

One future Product Owner decision should conditionally authorize all five waves, subject to green
readiness, only the next task being active, independent acceptance between waves, no change in
scope/identity/privacy/network/cost/license/risk, and no retry beyond the named budget.

A new Product Owner decision is required only for a vendor/tool change, proxy or license exception,
restart, extra retry, network-policy change, destructive cleanup, real-credential exposure,
candidate change, or final release decision. Normal pass-through review does not require another
approval.

## Estimate and alternative

With readiness completed first and no new external defect, remaining active work is approximately
**9–19 hours**, likely **2–4 calendar days** with review.

Alternatively, Product Owner may retain all evidence, label v0.5 a local developer preview, and
prioritize real-provider/frontend integration. A12 would remain explicitly unpassed and mandatory
before formal distribution. This is a scope decision, not a waiver.

## Decision boundary

This plan grants no execution authority. Next is one consolidated read-only readiness audit and
one Product Owner choice between full certification and the developer-preview route.
