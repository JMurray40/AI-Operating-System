# v0.5 Visible-Context Conversation Acceptance Tests

| Field | Value |
|---|---|
| Status | Proposed — Product Owner acceptance required |
| Scope | CLI and in-process application API; session-only; non-streaming |
| Evidence owner | Principal Engineer if separately authorized |
| Independent reviewers | Chief Architect / CTO, then Quality & Release |

## Evidence rules

Every executed result must bind exact branch, commit, tree, package digest, Python and Git
versions where relevant, dependency lock, OS, machine profile, command, fixture digest,
policy/adapter/contract versions, and raw samples. Private evidence must be digest-bound and
must not publish private paths or content. Historical candidate results are not evidence.

No passing aggregate can waive a security failure. Tests use synthetic fixtures by default;
any private-pilot or real-provider run requires separate named authorization.

## Provider and degraded-operation matrix

| Scenario | Expected result |
|---|---|
| No provider configured | Prepare and inspect work; dispatch is typed unavailable |
| Network disabled | Mock works; real dispatch fails safely without retry |
| Endpoint mismatch/redirect | Denied; redirects do not escape the allowlist |
| Provider timeout | One failed terminal attempt; draft/session retained only in memory |
| User cancellation | One cancelled attempt; no completed answer or retry |
| Malformed/oversized provider result | Withheld and failed; no raw payload rendered/logged |
| Citation validation fails after provider result | Provider prose withheld as an answer; typed evidence failure |
| Usage/cost absent | Completed answer may be shown with usage/cost `unknown` |
| Source changes after preview | Dispatch blocked; new prepare required |
| Policy changes after approval | Dispatch blocked; new approval required |

## Performance and resource matrix

Run deterministic prepare benchmarks at 100, 500, 1,000, and 5,000 notes with fixed query,
scope, graph, policy, snapshot, warm-ups, runs, construction boundary, Python, and machine.
Retain every raw timing and peak-memory sample and independently recompute p50/p95/p99.

Required gates:

- 5,000-note prepare p95 under 2 seconds;
- unchanged query stages no more than 20% slower than an equivalent accepted baseline;
- conversation application overhead excluding retrieval/provider p95 under 250 ms;
- cancellation acknowledgment p95 under 500 ms in a controlled adapter;
- hard configured limits stop oversized history, graph, context, prompt, response, and
  concurrent requests without unbounded memory growth.

Real-provider latency and cost are reported separately, not used to disguise application
latency. No timing of `blocked`, `not_found`, mock-only, or post-completion chunking can stand
in for successful real-provider evidence.

## Accessibility and CLI matrix

- complete keyboard operation and documented commands;
- context items have stable textual IDs and removal confirmation;
- color is optional and never the only status channel;
- plain text and JSON expose equivalent status, coverage, citations and limitations;
- terminal width and Unicode degradation do not hide policy or evidence status;
- cancellation is discoverable and acknowledged;
- no streaming announcement requirement is claimed because streaming is excluded;
- scripted mode has an explicit, auditable approval mechanism and cannot auto-approve a
  remote context through an interactive default.

## Packaging, installation and recovery matrix

- wheel payload is byte-bound to the reviewed executable tree;
- clean supported-environment install and installed-command verification;
- declared dependencies only, acquired under an approved online/offline boundary;
- deterministic fixture conversation with mock adapter;
- real-provider configuration rejects missing secret/endpoint safely without printing it;
- uninstall/reinstall from the same verified wheel;
- missing/corrupt derived state rebuilt without repairing canonical sources;
- uninstall leaves no transcript store because none is permitted;
- documentation-only non-author review reproduces the supported workflow.

## Privacy and human evaluation

The real-provider evidence package records provider, model role/configuration, endpoint,
data-use/retention disclosure, request count, usage, cost, and outcome without publishing
message text, excerpts, private paths, credentials, or source content. The user must be able
to identify what will be sent, remove an item, recognize model knowledge, open a citation,
and understand a policy block without instruction.

## Release stop conditions

Stop Engineering or review immediately on unauthorized egress, source/provider/canonical
mutation, excluded-source disclosure, hidden telemetry/fallback, approval mismatch,
cross-workspace leakage, stale or fabricated citation, secret/private-data leak, unbounded
resource behavior, a broadened write/tool surface, or evidence not bound to exact artifacts.

Passing this proposed matrix would support—but not replace—independent CTO and Quality
dispositions and Product Owner release authority.
