# v0.5 Visible-Context Conversation — User & Operator Guide

| Field | Value |
|---|---|
| Status | Engineering (WP1–WP3) — session-only; non-streaming |
| Surfaces | `jarvis chat` CLI and the in-process `ConversationApplication` API |
| Related | Handoff 07 (brief), Handoff 08 (authorization), Handoff 08a (WP1 corrections), ADR-0022/0023/0024 |

Conversation is an application layer over the released deterministic query/evidence
pipeline. It owns temporary, process-local cross-turn state and provider orchestration and
receives no vault-write, operational-store, tool, or general-network capability. All state
is erased on reset or process exit.

## 1. Concepts

A turn is a two-phase operation: **prepare** then **dispatch**.

1. `prepare` validates the workspace, scope, source root, and provider destination; applies
   authorization and sensitivity policy **before** retrieval; runs released retrieval and
   evidence services; and produces an **immutable context snapshot** with a SHA-256 digest.
2. You inspect the snapshot, optionally remove items (each removal is a **new** snapshot and
   digest), then grant a **digest-bound approval**.
3. `dispatch` re-validates approval, policy, credential presence, cost ceiling, and current
   source bytes, deterministically assembles the prompt within a hard budget, and performs
   **exactly one** complete-response request through the selected adapter.

Every material claim in an answer is typed `fact`, `inference`, `model_knowledge`,
`unknown`, or `assumption`. Facts require citations that validate against current bytes;
model knowledge is shown as not vault-supported. Coverage is `complete`, `partial`,
`incomplete`, or `none`. No numeric answer confidence is emitted.

## 2. CLI usage (`jarvis chat`)

Scripted mode (one prepared turn per invocation):

```
# 1) Inspect: prepare and print the context manifest (no dispatch, no network).
jarvis chat "summarize the AI Operating System project" --session-id s1 --as-of 2026-08-01T00:00:00+00:00

# 2) Approve the EXACT digest shown in the manifest, then dispatch through the mock adapter.
jarvis chat "summarize the AI Operating System project" --session-id s1 --as-of 2026-08-01T00:00:00+00:00 \
    --approve sha256:<digest-from-step-1>
```

Because the snapshot digest binds the session id and evaluation time, reproduce a digest
across the inspect and approve steps by passing the **same** `--session-id` and `--as-of`.

Options: `--path` (vault dir), `--project` (exact ADR-0018 selector), `--provider`
(`mock` or `google`), `--remove C2,C3` (drop context items before approval), `--approve
<digest>`, `--trace`, `--format {text,json}`, `--interactive`.

Interactive mode (`--interactive`) runs an in-process REPL with `/prepare`, `/manifest`,
`/remove`, `/approve`, `/dispatch`, `/retry`, `/history`, `/trace`, `/reset`, `/help`,
`/quit`.

Text and JSON render one semantic result (status, coverage, citations, limitations,
usage/cost provenance, one-based turn number). Status and coverage are always textual, never
color-only, and JSON has structural parity with text.

### Exit codes

| Code | Meaning |
|---|---|
| 0 | success (manifest printed, or a completed dispatch) |
| 3 | user declined or cancelled |
| 4 | policy/eligibility block before dispatch |
| 5 | provider/credential/network unavailable |
| 6 | request/snapshot/evidence/approval validation failure |
| 7 | internal failure |

## 3. Provider boundary and Google configuration

The mock adapter is deterministic, offline, and the only dispatchable destination in this
build. The **Google Gemini** adapter (`jarvis_core.providers.google_gemini`) is implemented
against a fake transport and bounded loopback capture only; **live calls and real
credentials are not activated** until a separate real-provider authorization (WP4).

Approved profile (domain identity kept separate from the native model — never a LiteLLM
composite string):

```text
provider_id: google-gemini-developer-api
model_id:    gemini-3.5-flash-lite
host:        generativelanguage.googleapis.com  (https)
operation:   generateContent  (non-streaming, thinking_level=minimal)
```

The adapter adds only an allowlisted `content-type` and an opaque `x-goog-api-key` header,
enforces the exact host/scheme/operation, follows no redirect, inherits no proxy, and emits
no telemetry, fallback, or hidden retry. The wire field shapes are implemented from the
documented Google REST contract and **must be reconfirmed at the WP4 preflight**.

**Credentials.** The production `EnvCredentialProvider` reads `GEMINI_API_KEY` from the
process environment through an injectable mapping. `is_available()` answers presence only —
no network, no key validation, and the secret never enters a snapshot, approval, prompt,
trace, error, or log. The CLI wires no credential provider, so a Google destination fails
closed at prepare with `unavailable_credential`.

**Data-use disclosure.** Google may process and retain request data per its published API
terms and abuse-monitoring policy; zero data retention is **not** claimed. "Session-only"
describes Jarvis storage, not the provider's retention.

**Cost.** A versioned price table produces a per-request estimate checked against the
`USD 0.05` per-request ceiling before dispatch; the exact pricing is reconfirmed at the WP4
preflight before any real spend. Usage and cost carry explicit provenance (`reported`,
`estimated`, or `unknown`); an absent value is shown as `unknown`, never zero.

## 4. Degraded operation

| Scenario | Result |
|---|---|
| No credential (remote) | Prepare fails closed with `unavailable_credential`; dispatch unavailable |
| Endpoint/scheme/operation escape | Denied; no request is sent |
| Redirect / proxy | Not followed / not inherited; one attempt, no fallback |
| Provider timeout | One failed terminal attempt; no retry |
| Malformed / oversized result | Withheld and failed; no raw payload rendered |
| Citation validation fails | Answer withheld; typed evidence failure |
| Source or policy changed after approval | Dispatch blocked; a fresh prepare/approval is required |

## 5. Testing and benchmark protocol

- Unit + integration tests map the C01–C30 acceptance IDs (`tests/unit/test_conversation_wp1.py`,
  `tests/unit/test_conversation_wp1_08a.py`, `tests/unit/test_conversation_wp2.py`,
  `tests/integration/test_cli_chat.py`).
- Deterministic benchmark: `python scripts/benchmark_conversation.py --sizes 100,500,1000,5000`.
  Gates: 5,000-note prepare p95 < 2 s; application overhead p95 < 250 ms; cancellation
  acknowledgement p95 < 500 ms; bounded peak memory. Raw samples and percentiles are retained
  in the emitted JSON.

## 6. Packaging, installation, and recovery

The conversation package ships inside the same `jarvis-core` wheel and console entry point as
the released CLI; building and installing the wheel uses the released packaging mechanism
(no new runtime dependency is added — standard library only).

- **Offline fixture rerun:** `jarvis chat "<question>" --session-id s --as-of <T>` then
  `--approve <digest>` exercises the full pipeline with the mock adapter, no network.
- **Missing-credential / provider-unavailable:** `--provider google` prepares and then fails
  closed without printing any secret.
- **Uninstall/reinstall:** reinstall the same verified wheel; behavior is unchanged.
- **Recovery:** conversation state is session-only, so there is nothing to recover after a
  crash — a new session starts clean. Derived query structures rebuild from canonical sources
  via `jarvis resume-doctor` (never repairing canonical sources). Uninstall leaves no
  transcript store because none is created.

## 7. Security, privacy, and limitations

- Deny-by-default at source, context, egress, adapter, rendering, and retry boundaries.
- No tool or write capability; no provider call during prepare/inspection/removal.
- Excluded (unauthorized) sources cannot influence any request-visible surface; only a safe
  aggregate count is exposed.
- Provider output is sanitized before display: no active HTML, remote images, data/javascript
  URLs, autolinks, or control characters.
- Trace is an allowlisted event audit — no message bodies, excerpts, secrets, raw payloads,
  private paths, or excluded identities.
- **Known limitations:** non-streaming only; no durable transcript, resume-across-processes,
  archive, search, export, or provider memory; project scope expands exactly one authorized
  graph hop (≤25 neighbours); real-provider evidence is deferred to WP4.
